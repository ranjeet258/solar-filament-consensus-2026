# Solar filament segmentation: model consensus

Source-only release for Kaggle competition `filament-segmentation-2026`.

## Run the submitted notebook

Open `solar_filament_hybrid_v2.ipynb` in Kaggle and attach the competition plus
the outputs of these four training notebooks:

- `ranjeet258/sf-seg-train-v1`
- `ranjeet258/sf-seg-train-v2`
- `ranjeet258/sf-seg-train-v3`
- `ranjeet258/sf-yolo-v1`

The saved runnable notebook is
<https://www.kaggle.com/code/ranjeet258/solar-filaments-cross-model-consensus-v2>.
Default execution runs on CPU, installs the pinned post-processing dependencies,
validates 177 images never seen by the YOLO network, learns four selectors,
and writes `/kaggle/working/submission.csv` and `hybrid_v2/report.json`.

It uses saved probability maps and YOLO proposals from the declared training
outputs. It does not replay an embedded submission CSV. The training-output
inputs must be accessible to whoever reruns this cached route. Fresh training
source for every network is included in the notebook and `training/`.

## Method

Three U-Nets (ResNet34, ResNeXt50 and EfficientNet-B4) learn soft shape and
presence targets from the competition's multiple annotators. Their foreground
maps are averaged. A separately trained YOLO11m segmentation model provides
whole-instance proposals. We also generate YOLO proposals with a two-pixel
boundary band refined by the U-Net foreground. LightGBM uses shape, foreground
support, YOLO confidence and cross-model agreement to predict expected matched
IoU per annotator. Configuration selection compares semantic-only, raw-hybrid,
refined-hybrid and combined sources. Greedy selection clips small overlaps and
rejects large overlaps before COCO RLE export.

## Validation and limitations

YOLO held out network fold 0: 177 of 707 training images. All fusion learning and
validation is restricted to those images. Four meta-validation folds group by
observation day. Test scores average the four fitted selectors. The original
network folds group duplicate annotator sets by physical image, not by day.

Configuration selection uses cross-fitted predictions; its outer settings
estimate does not retrain selectors in a complete second nested loop. Report it
as an estimate, not as an unbiased final evaluation. Local PQ is computed against
each annotator set with strict IoU > 0.5, then pooled using the official PQ
formula. Only actual Kaggle receipts establish public leaderboard scores.

The older 0.55 public result used an embedded prediction CSV from
`lamhuy8904/solar-filament-unet-segmentation-0-55`. Its generating weights are not
provided by that source. It is not the independently trained performance of
this release and is not generated by this notebook. Optional local reference
fusion experiments are labelled separately and are not reproducible from
available reference weights.

## Fresh training

Use separate GPU sessions for `training/train_v1.py`, `train_v2.py`,
`train_v3.py`, and `train_yolo.py`, each with the competition attached. The U-Net
scripts train four folds, write EMA weights, and export eight-view TTA maps.
YOLO uses one sample per annotator set and holds out network fold 0. Preserve
each session's output and attach it to the fusion notebook. Use
`requirements-training.txt` as a pinned starting environment; the historic
training runs installed their dependencies dynamically, so the exact historic
training environment cannot be reconstructed from the original source alone.
GPU and package differences can prevent bitwise-identical retraining.
